# Security Policy

## Supported versions

Security fixes are provided for the latest released `0.1.x` version.

## Reporting a vulnerability

Please do **not** open a public issue for a vulnerability, especially one that includes an unredacted secret or a redaction bypass sample.

Report privately through the repository's GitHub Security Advisory "Report a vulnerability" flow. Include a minimal synthetic reproduction, affected version, impact, and any suggested mitigation. If that flow is unavailable, contact the maintainer through the repository owner profile and do not include live credentials.

We aim to acknowledge reports within 7 days and will coordinate a fix and disclosure timeline with the reporter. Do not exploit the issue beyond what is necessary to demonstrate it.

## Scope

`issuebrief` performs best-effort local redaction. A missed pattern is valuable to report, but generated output must always be manually reviewed before sharing.
